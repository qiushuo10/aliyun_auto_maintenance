# **统一安全网关审计中心 (Unified Security Gateway Audit Center) — 功能描述与设计规范**

本模块作为阿里云运维 Agent 的**系统级安全黑匣子**，负责全量归档、存储并呈现系统通过网关发出的所有操作行为。该模块旨在提供完全的运维透明度，确保任何一次自动化的 API 调用或定时任务触发，都能实现物理层面的溯源与审计。

## **1\. 产品定位 (Product Positioning)**

审计中心是“确定性运维”的最后一道防线。它将 Agent 的所有行为转化为“本地可追溯审计日志”，通过对本地 app.db 中 tool\_invocations 表的实时读取与呈现，确保运维人员随时掌握：**“哪一个 Profile 在什么时间、通过什么工具、对哪个 endpoint 发起了什么请求，结果如何”**。

## **2\. 核心功能点 (Functional Specs)**

### **2.1 全量行为实时观测 (Full-Scope Observability)**

* **实时追加记录**：系统发生的每一项关键动作（包括：定时任务触发、网关安全自纠错请求、工具调用、人工确认授权）均会增量追加写入本地 tool\_invocations 表，无需手动刷新即可实时反映至界面。  
* **调用溯源归档**：详细记录调用方法 (Caller Tool / Action)，不仅包含业务动作，还包含系统底层的 discover\_api、get\_api\_params 等辅助链路调用，便于回溯 Agent 决策依据。

### **2.2 网关执行状态可解释性 (Execution Transparency)**

* **状态映射**：直观展示网关对执行结果的判断，如 SUCCESS \- 周期引擎自动放行 或 REJECTED \- 用户人工阻断。  
* **链路分析**：支持通过对比“绑定的目标 Endpoint”与“调用方法”，快速识别请求的去向及合法性。

### **2.3 凭证合规溯源 (Credential Accountability)**

* **授权标识追踪**：审计表明确记录“授权使用 AK 标识”，通过脱敏处理显示对应的 AK 缩略信息。这保证了在多 Profile 共存的复杂场景下，任何一次异常变更都能通过凭证链直接定位到具体的“配置主体 (Profile)”。

## **3\. 设计规范与安全纪律**

### **3.1 本地存储优先 (Local-First Compliance)**

* **数据不出域**：所有审计数据强制落盘于本地 app.db，禁止通过任何方式上传至云端或第三方服务端。  
* **合规性声明**：在审计中心底部显式标注安全准则：*“本地桌面客户端仅加密发起调用，凭证从不上云，从物理层面杜绝泄漏风险。”* 这一声明旨在为企业运维合规检查提供明确的心理建设与设计证明。

### **3.2 易用性设计 (UI/UX Guidelines)**

* **简洁高效的表格流**：采用紧凑的表格布局，以时间线逆序排列（最新发生的事在最上方），确保运维人员处理紧急故障时能第一眼定位最新的异常记录。  
* **高对比度反馈**：执行成功（SUCCESS）标记为绿色调，执行拦截（REJECTED）标记为红色调，通过视觉差异缩短运维人员的故障响应时间。

## **4\. 应用价值**

* **故障归因溯源**：当生产环境出现未预期的 API 变更时，运维人员可通过该中心迅速查看是谁（哪个 Profile）、在哪个时间点触动了哪个 API。  
* **安全自检闭环**：通过该中心记录的 REJECTED 拦截日志，系统后台引擎可定期扫描这些“失败的尝试”，自动提炼出新的运维教训，并将其升维为全局 Playbook 技能，从源头上减少 Agent 的错误调用概率。

这个文档定义了该模块的专业职责。v1 不提供企业合规导出、签名导出或 hash chain；页面只实现本地查询、过滤与详情追溯。

# **周期性自愈守护与调度中心 (Cyclic Healing & Scheduling Hub) — 功能描述与设计规范**

本模块是阿里云运维 Agent 的“后台执行大脑”。它通过常驻系统的 Daemon 进程，执行各类周期性运维资产轮巡与系统自愈任务，确保 Agent 在用户离线时仍能维持云上业务的稳定性与健康度。

## **1\. 产品定位 (Product Positioning)**

调度中心是 Agent “自动化”与“智能化”的连接点。它通过对运维资产的周期性扫描与智能巡检，将单纯的“交互式问答”扩展为“全天候守护”。该模块的核心设计哲学是“透明执行、安全可控、自主繁衍”。

## **2\. 核心功能点 (Functional Specs)**

### **2.1 任务分类调度 (Dual-Task Categorization)**

* **业务运维任务 (Business Tasks)**：  
  * 覆盖云上资源层面的健康巡检，例如 ECS 实例状态轮巡、OSS 存储冗余检查、安全组规则合规扫描等。  
  * 具备“首选授权”机制，确保高危写操作在首次运行前必须获得用户的物理签署授权，符合安全合规要求。  
* **系统自愈任务 (System Self-healing Tasks)**：  
  * Agent 自身的“反思与进化”系统。包括：自动提炼历史错误日志中的逻辑陷阱、重构无效代码、自动压缩并备份本地 app.db 事实库，保持系统的高性能与高鲁棒性。

### **2.2 任务视察与控制 (Task Deep Inspector)**

* **执行流透明化**：通过右侧的“视察窗”，用户可以查看任务后台运行的受限 DSL / action graph、由 DSL 编译出的只读 JS 预览，以及精确到毫秒的执行记录，消除后台任务的“黑盒”隐患。  
* **状态即时切换**：  
  * **🎮 暂停/恢复调度**：一键挂起特定任务，防止在紧急业务变更期间产生的冲突或误触。  
  * **⚡ 立即触发测试**：强制触发任务执行一次巡检逻辑，便于运维人员快速验证特定修复方案的有效性。

## **3\. 安全纪律与交互规范**

### **3.1 物理授权护栏 (Physical Authorization Guard)**

* **高危操作阻断**：所有标记为 dangerous 的周期性写任务，均强制锁定为“待授权”状态。用户必须在界面中通过双重验证，方可允许后台 Daemon 进程在绑定脚本 hash、Profile、Workspace、参数范围和有效期内执行；免签模式也不能自动执行 dangerous。

### **3.2 运行状态反馈 (Live Feedback)**

* **动态运行日志 (Live Log Stream)**：所有定时任务均伴随实时日志流，使用绿色/黄色/红色状态条清晰表达任务的运行健康状态。若出现执行故障，系统将自动触发高亮告警，并将其记录至审计中心。

## **4\. 自进化逻辑 (Self-Evolution Logic)**

* **智能升格 (SOP Promotion)**：系统自愈任务通过分析后台巡检发现的故障趋势，自动将其封装为“全局 Playbook 技能”。这种自动进化机制确保了 Agent 随着使用时长增加，其运维能力呈现指数级增长。

## **5\. 设计规范 (UI/UX)**

* **分栏式结构**：左侧为任务列表清单，右侧为详情视察器，支持快速点击切换任务，避免页面频繁跳转。  
* **简洁的状态标识**：使用简洁的图标（Running, Pending, Failed）快速传达任务生命周期。  
* **安全性警示**：对于正在执行高危任务的操作区域，提供明显的视觉引导（如警告黄色底色），提示用户任务涉及写操作权限。

这个模块的设计确保了即使在您不操作工作台的时候，Agent 依然能通过后台的“心脏跳动”时刻保持对云端资产的监控与维护。v1 聚焦任务创建、首次签署、运行视察和审计追溯，不包含批量导出/导入或企业合规导出。
